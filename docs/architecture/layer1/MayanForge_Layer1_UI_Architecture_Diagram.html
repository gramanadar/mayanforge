1 · Target architecture

Layer 1 renders projections and drafts, and sends commands; it never decides anything. Every read, write and generation request goes through Layer 2; identity is handled by the Layer 2 BFF and an external OIDC provider.

  • Never change state optimistically for a gated action or a generate request; show a pending state until the event or draft arrives.
  • Every mutating call sends an Idempotency-Key; versioned resources send If-Match; errors are RFC 9457 problem details with stable codes (403, 409 stale, 412, 422, 429).
  • Show lastEventAt and a stale banner when the projection lags; never show a verdict or sign-off for a different candidate digest.
  • Before reopening an approved baseline, show which approvals the cascade will invalidate.
  • No secrets, tokens or raw evidence in browser storage; downloads use short-lived grants.

2 · Build board ↔ Layer 3 task states

The four Build steps (Plan, Approve, Run, Integrate) sit above this board. After the plan is approved, one “Start build” begins the run; the board is the Run step, and each column is one or more Layer 3 task states.
