How to use this registry

1. Select M0 and reconcile every entry with its original source section. Break broad headings into atomic child requirements without changing existing MF IDs.

2. Approve milestone ownership, dependencies, acceptance tests, and task IDs before marking features Ready.

3. Implement M1, M2, and subsequent milestones in sequence. A feature becomes Verified only when supporting evidence exists.

4. Export progress JSON and commit it to the repository. Browser-local progress is not synchronized with GitHub or other users.

5. Keep the machine-readable registry JSON in version control. Use an explicit change review when reassigning a milestone, splitting a feature, or retiring a capability.
